# The frontier stubs — the ranked set of next milestones

*Every row is a full stub in `plans/` (the stub rule, `CLAUDE.md` § The pipeline). **This file holds current state only**: each
filing rewrites it in place, and the history of rankings, re-scopes and closures is in git. **Maintenance:** each time a milestone
reaches Derived, Poros drafts and Keryx files the open milestones, adds every candidate the milestone surfaced as a stub file,
re-ranks the table with each row's bearing on the answer stated honestly (`CLAUDE.md` § Counter-priors, rule 1), moves finished or
demoted stubs to the closed list with one line (and a banner in the stub file), and mirrors the top three into `CLAUDE.md` § Paths
forward. **Milestone numbers are permanent identifiers**: after every edit, check that each `M-nn` appears exactly once as a row,
because a number lost from the table is a milestone nobody will find.*

**The ranking rule.** Name each stub's object in the vocabulary of the classical theory it already belongs to, and let that theory
decide the question's shape before any search runs (`CLAUDE.md` § Method, recognize the classical theory first). Prefer a stub whose
question becomes a finite exact computation plus a named theorem over one that searches for an object; a stub with no such
recognition is a reading room, not a milestone. Rank by bearing on the answer, never by difficulty or formalization effort.

**How a milestone is chosen.** Poros ranks and chooses; the principal may override, because the aim is theirs.
